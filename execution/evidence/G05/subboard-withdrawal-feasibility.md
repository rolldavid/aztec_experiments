## Finding and smallest useful campaign

A no-post withdrawal after rejection can demonstrate that the board rejection does not directly disable `withdraw`, but cannot establish recovery from a post already made to that board. The necessary full case is: actual funded claim -> create authentic subboard -> post to it -> authorized rejection -> mature and screen that same private history -> L2 withdrawal -> official controlled local Outbox settlement -> actual original-depositor L1 refund. Keep one funded human actor for this focused case; fee-only creation by a second actor remains the separate subboard acceptance scenario, not a prerequisite to duplicating two-account setup here.

This requires four user action proofs after claim (create subboard, post, screen, withdraw), one moderator rejection transaction, and one L1 refund transaction. Initial deployment/READY/activation/private-fee funding/claim keep their existing genuine setup. No new name or Bok model transaction is needed. It is smaller than appending full exit to the already broad subboard policy/update case. A new blocked-post prepare after rejection must use the exact structured rejected-board classifier, with zero proof/send and no generic outage-as-pass; local auth-witness simulation may occur.

## Contract and exact ABI

It preserves metadata/rules/version; it does not change deposit state or per-post penalty flags. `_publish` at 895 onward rejects new posts into the board. Rejection itself is not a timely post penalty.

`screen(deposit_chain_id:Field, child:Option<HintedNote<PostNote>>, grandchild:Option<HintedNote<PostNote>>)` at 884 calls `Admission::consume(..., 0, true, ...)`, without a subboard-status precondition. The actual normal processed artifact has these three user parameters (the raw private ABI also has generated context `inputs`). Use the production Some/None conversion already in application.mjs, not undefined-as-Option guessing.

Admission at 580–741 pops the owner's exact deposit and authenticates the NHK-bound successor note. At 631–690 it checks the real post's canonical inclusion timestamp, exact censor deadline and historical flag. For one real entry, maturity requires canonical anchor timestamp >= post inclusion timestamp + configured censor window; child is required and grandchild is None. Screening creates a dummy history entry and replacement deposit; it must NOT increase the public post count. Logical ten-field state keeps first four receipt fields unchanged, advances head sequence 1->2, screened sequence 0->1, last-real sequence remains 1, and screened link equals the prior real head. Verify actual recomputed debt rather than assume rejection clears it.

`withdraw(deposit_chain_id:Field)` at 747–769 selects/pops the owner's private deposit, validates original amount/depositor and portal, requires screened_sequence >= last_real_sequence and anchor time >= next_allowed_time, then emits V1 exit content to that portal. No subboard check. This is a source argument only until the real rejected-board sequence executes.

## Smallest parent interface

One lifecycle-free consumer can accept `{actor, action, createSubboard, rejectSubboard, readDeposit, readPostAdmission, waitCanonicalAnchor, projection, settleAndRefund}`. `action` is the parent's already journaled production action. `readDeposit`/physical-note checks remain trusted/private in-memory. `waitCanonicalAnchor(requiredTimestamp)` belongs to the existing miner/checkpoint owner, bounded by ctx.applicationDeadlineAt. `settleAndRefund` receives only the actual checked exit capture in trusted memory and delegates the two existing C01 helpers after the real-wall miner has unwound (never two miners). It returns aggregate receipt/accounting facts. Parent owns source binding, exact failure classification, fee accounting and canonical transaction evidence. A small extra reader for post flag deadline can use existing canonical post-state APIs; do not infer maturity from wall clock alone.

Required oracle sequence: rejection preserves original private receipt fields/debt; failed new-post preparation leaves it unchanged; early exit rejects for unscreened history; mature screen consumes exactly old deposit nullifier, yields exact successor/dummy, preserves amount/depositor and public post count; exit consumes exactly successor nullifier, leaves no active replacement deposit and emits one exact exit leaf; actual canonical L1 refund consumes that witness once and returns the full collateral less only L1 gas. Reconcile every user PrivateFPC debit to canonical L2 fees and pool delta; moderator fee separate. UI tombstones and directory rejection remain navigable throughout. Public report retains boolean attribution outcomes and public tx/leaf/receipt hashes, never owner/name/note grouping or raw private note fields.
