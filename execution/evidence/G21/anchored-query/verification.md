# Checkpoint read availability

The browser gateway previously selected its checkpoint-aware read policy only when the optional compact-block endpoint was configured. Both hosted query services lacked that option. Consequently, even a PXE request with a fixed canonical block number/hash could be rejected during proposed-head synchronization. The observed 331 ms HTTP503 for findLeavesIndexes came from the gateway readiness/anchor boundary; its exact rejected snapshot was not retained.

The policy now classifies authenticated checkpoint reads independently of compact-block transport. Exact state anchors newer than the checkpoint escalate the whole batch to strict proposed readiness before dispatch. Canonical hashes, retention, pre/post fences, unknown/pending transaction handling and strict mutation/simulation checks remain enforced. There is no new intermediary, retry of transaction submissions, or deadline on transaction/bridge completion.
